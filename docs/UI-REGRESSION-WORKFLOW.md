# UI regression workflow

## Code checks

`npm run grimoire:check` is run automatically by `npm run grimoire:install`.
It exercises the actual Lua controls: anchors, bounds, clipping through the scroll child,
ancestor visibility and opacity, glyph drawing layer, native actions, layouts, states,
assets, installation and rollback. Deliberately broken controls must fail these checks.

The mock records unsupported API calls. Strict UI mode rejects them; currently the strict
renderer check covers the glyph helpers, not every WoW screen. Run
`npm run grimoire:audit` to inspect remaining simulation limits. Font metrics, actual
texture overdraw, animation and non-unit scale are not certified by the mock.
A local preview is not a WoW screenshot.

## Install and recover

`npm run grimoire:install` checks the code, snapshots the existing installed addon and
copies the update. It preserves Inbox.lua and never touches SavedVariables.
Installation is allowed before visual approval so the current build can be reviewed.

`npm run grimoire:rollback` restores the latest snapshot for the configured installation.
Use `npm run grimoire:rollback -- BACKUP_ID` to select an older one. It verifies backup
hashes and paths before changing files. Modified new files are not silently deleted.
Snapshots are local under backups/grimoire and are ignored by git. No snapshot is
called visually approved merely because it was installed.

## In-game review

1. Run `npm run grimoire:review:prepare`. This creates a PENDING review tied to a SHA-256
   fingerprint of the addon Lua and runtime assets. Live Inbox.lua is excluded.
2. Install and reload the addon. Capture PNGs in the WoW client for each combination:

   | Window size in UI units | States |
   | --- | --- |
   | 900 x 600 | disconnected, connected, responding |
   | 1180 x 830 | disconnected, connected, responding |
   | 1600 x 1000 | disconnected, connected, responding |

3. Attach each real capture, for example:
   `npm run grimoire:review:attach -- 900x600 connected C:\captures\connected.png`.
   The command copies the image, computes its hash, and resets approval to pending.
4. In the review.json path printed by prepare, record the human reviewer, client version,
   reviewedAt (ISO timestamp), and observed interaction results: copy, resend,
   delete/undo, Config, all scrollbars, resize, minimize/restore, opacity, send/stop and overlapping another addon window (click each window in turn).
   Mark status approved only after inspecting the actual captures and interactions.
   Captures must be legible PNGs of at least 640 x 400 pixels; desktop captures may
   include the game around the window. Declared window dimensions are UI units.
5. Run `npm run grimoire:release-check`. Packaging also invokes the visual guard.

The release guard checks all nine captures, distinct image hashes, PNG decoding,
review fields and interaction results against the exact current runtime fingerprint.
It does not judge artistic quality or prove image provenance automatically; those
remain the human reviewer's responsibility. Never fill approval fields on the strength
of unit tests. A changed build needs new evidence. No screenshots are generated by the
review tooling, and its synthetic test fixtures stay outside real review directories.

## Status language

- Code checked: automated checks passed.
- Visual review pending: no matching human review exists.
- Visually reviewed: matching client evidence and human review passed the release guard.

These labels are independent; passing code checks never grants visual approval.

Window coexistence: the main chat and mini bar use normal MEDIUM toplevel windows, with grouped render layers when the client supports it. Dialogs retain their modal layer. No foreign addon frames are edited, and background renders do not raise the chat. Actual cross-addon ordering still needs the client overlap check.
